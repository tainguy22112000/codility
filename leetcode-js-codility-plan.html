1.10 Common Pitfalls

  1. arr.sort() without a comparator sorts as strings ([10, 9, 1] → [1, 10, 9]).
  2. shift() / unshift() are O(n); don't use them in big loops.
  3. 0.1 + 0.2 !== 0.3: floating point; compare integers where possible.
  4. for...in on arrays gives string indexes; use for...of.
  5. Math.max(...hugeArray) can crash for very large arrays (100k+); use a loop.
  6. slice copies, splice mutates, and sort/reverse mutate.
  7. [] == false is true; always use ===.

2. Arrays & Strings

Overview

Fundamentals

An array stores elements in consecutive memory slots, each reachable by its index. That layout gives arrays their performance profile:

Operation JS Cost
Read / write by index a[i] O(1)
Add / remove at the end push, pop O(1)
Add / remove at the front or middle unshift, shift, splice O(n), because every later element shifts
Search for a value indexOf, includes O(n)
Copy slice(), [...a] O(n) 
index:   0   1   2   3   4   5
value: [ 7 | 1 | 5 | 3 | 6 | 4 ]      a[2] -> 5 instantly

A string behaves like a read-only array of characters. You can read s[i], but you can't assign to it. To "edit" a string, convert it to an array, change the array, then join(""). Careful: building a string with += inside a big loop creates a new string each time, so collect pieces in an array instead.

The core idea: one pass with a running value

Most beginner array problems look like they need to compare every pair of elements. The faster approach is to scan once and carry a small summary of everything seen so far (a running sum, min, max, count, or previous value). At each position you answer "given what I know so far, what is the best answer ending here?" and update the summary.

scan left -> right        summary so far      decision at this element
[ 7 | 1 | 5 | 3 | 6 | 4 ]   min = 1           profit today = 5 - 1

Prefix sums (a second tool)

A prefix array stores the sum of everything before each index: prefix[i+1] = prefix[i] + a[i]. After one O(n) pass, any range sum a[i..j] is prefix[j+1] - prefix[i] in O(1). Use it when a problem asks many range-sum questions.

What problems look like this

  • "Return the max / min / total / count of something over the array."
  • "For each element, compare against everything before (or after) it."
  • Reversing, merging or scanning strings character by character.
  • The obvious solution is a double loop over all pairs, and N is large (Codility often uses 100,000).

Problem Example

Best Time to Buy and Sell Stock. prices[i] is the price on day i. Buy once, then sell on a later day. Return the max profit, or 0.

  • [7,1,5,3,6,4] → 5 (buy at 1, sell at 6)
  • [7,6,4,3,1] → 0

Details Explanation

Step 1: the brute force and why it's too slow

Try every pair (buy day i, sell day j > i) and keep the largest prices[j] - prices[i]:

for (let i = 0; i < n; i++)
  for (let j = i + 1; j < n; j++)
    best = Math.max(best, prices[j] - prices[i]);

With n = 6 that's 15 pairs. With n = 100,000 it's about 5 billion, which fails Codility's time limit. O(n²).

Step 2: find the redundant work

Fix the selling day j. Which buy day gives the best profit for that sale? Obviously the cheapest price before day j. All the other buy days for that same sale are wasted comparisons, so we never need to look at them individually. We only need one number: minPrice so far.

Step 3: define the two variables

  • minPrice: the lowest price seen up to today (start at Infinity so the first price replaces it).
  • best: the largest profit found so far (start at 0, because "don't trade" is allowed).

Step 4: the rule at each day p

  1. If p < minPrice, today is a new cheapest day: update minPrice. (Selling today would lose money, so skip the profit check.)
  2. Otherwise compute p - minPrice. If it beats best, update best.

Step 5: trace [7, 1, 5, 3, 6, 4]

Day Price minPrice after Profit if sold today best after
0 7 7 n/a 0
1 1 1 n/a (new low) 0
2 5 1 4 4
3 3 1 2 4
4 6 1 5 5
5 4 1 3 5

Answer: 5. For [7,6,4,3,1] the price only falls, so minPrice keeps updating and best stays 0.

Step 6: complexity

One loop, O(1) work per element → O(n) time, two variables → O(1) space.

Edge cases to test

Empty array (loop never runs, returns 0), single day (0), all equal prices (0), strictly decreasing (0).

Solution

function maxProfit(prices) {
  let minPrice = Infinity;
  let best = 0;
  for (const p of prices) {
    if (p < minPrice) minPrice = p;       // new cheapest day
    else best = Math.max(best, p - minPrice); // sell today
  }
  return best;
}
// Time O(n), Space O(1)

Summary

  • Think "one pass + running variables" before nested loops.
  • Prefix sums turn range-sum queries into O(1): prefix[j+1] - prefix[i].
  • For strings, convert to an array, edit, then join("").
  • Watch edge cases: empty array, a single element, all negatives.

When Do I Use This?

  • Input is a list/string and you need one answer from scanning it (max, min, count, total).
  • You need to compare each element with "everything before it".
  • The brute-force answer is a double loop over pairs.

3. Hash Map / Set

Overview

Fundamentals

A hash table turns a key into an array position using a hash function, so it can find, insert and delete by key in O(1) on average, without scanning. JavaScript gives you two built-in versions:

Structure Stores Typical use
Map key → value counting, remembering an index, grouping
Set unique values only "have I seen this?", removing duplicates 
const seen = new Set();   seen.add(5);   seen.has(5);      // true, O(1)
const count = new Map();  count.set("a", 1);  count.get("a"); // 1, O(1)

Array lookup (is 9 present?)        Set lookup (is 9 present?)
scan [4,8,2,9,...]  -> O(n)         hash(9) -> bucket -> yes/no  -> O(1)

Notes: object keys always become strings, so prefer Map for numeric keys or when you need .size. If a key is missing, map.get(k) returns undefined, so use map.get(k) ?? 0 for counters.

The core idea: trade memory for speed

Many problems repeat the same question: "does value X exist somewhere else in the data?" Answering it by scanning costs O(n) per question, O(n²) overall. If you store every value as you go, each question becomes O(1). You spend O(n) extra memory to cut the time from O(n²) to O(n).

Three patterns to recognize

  1. Frequency counter: count how many times each item appears (anagrams, majority element, first unique character).
  2. Seen set: detect duplicates or cycles (if (seen.has(x)) ...).
  3. Complement lookup: for each x, look for the partner you need (target - x) among earlier items.

What problems look like this

  • "Does any value repeat?", "How many times does each appear?", "Do these two collections contain the same items?"
  • You need to match an element with something else and order doesn't matter.
  • The brute force repeatedly searches the same array inside a loop.

Problem Example

Two Sum. Given nums and target, return the indices of the two numbers that add up to target (exactly one solution).

  • nums = [2,7,11,15], target = 9 → [0,1]
  • nums = [3,2,4], target = 6 → [1,2]

Details Explanation

Step 1: the brute force

Check every pair (i, j) and test nums[i] + nums[j] === target. That's O(n²) pairs.

for (let i = 0; i < n; i++)
  for (let j = i + 1; j < n; j++)
    if (nums[i] + nums[j] === target) return [i, j];

Step 2: find the repeated question

Fix i. The inner loop is really asking, "is there a number equal to target - nums[i] somewhere in the array?" That is a pure lookup question, and a lookup is exactly what a hash map is fast at.

Step 3: decide what to store

We need the index of the partner, not just whether it exists, so the map stores value → index.

Step 4: why we only look backwards

For a valid pair (a, b), whichever number comes second will find the first one already stored. So at each element we (1) check whether the complement is already in the map and (2) only then store the current number. This also guarantees an element is never matched with itself.

Step 5: trace nums = [3, 2, 4], target = 6

i x need = 6 − x map before Found? map after
0 3 3 {} no (the map is empty, so 3 can't pair with itself) {3:0}
1 2 4 {3:0} no {3:0, 2:1}
2 4 2 {3:0, 2:1} yes → index 1 n/a

Return [1, 2]. For [2, 7, 11, 15], target 9: at 7 the need is 2, which is already stored at index 0, so the answer is [0, 1].

Step 6: complexity

Each element does one lookup and one insert, both O(1) → O(n) time. The map can hold up to n entries → O(n) space.

Common mistakes

  • Storing before checking (pairs an element with itself).
  • Using an object {} and getting "1" vs 1 key surprises.
  • Forgetting that duplicates overwrite: [3, 3], target 6 works because we check before we store the second 3.

Solution

function twoSum(nums, target) {
  const seen = new Map(); // value -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [];
}
// Time O(n), Space O(n)

Summary

  • Frequency counter: map.set(k, (map.get(k) ?? 0) + 1).
  • Set = fast "seen before?" check.
  • Complement pattern: store what you've seen, look up what you need.
  • Keys in plain objects become strings; prefer Map for numeric keys.

When Do I Use This?

  • You need to find duplicates, pairs, counts or "first unique".
  • Order doesn't matter and you need O(1) membership tests.
  • Anagram or grouping problems (key = sorted string or character count).

4. Two Pointers

Overview

Fundamentals

The two-pointer technique scans an array (or string) with two index variables instead of one. Because both pointers only move in one direction each, together they make at most about n moves, so the whole scan is O(n). Compare that with a nested loop that looks at every pair, which is O(n²).

There are two common setups:

Setup Starting positions Movement Typical problems
Opposite ends left = 0, right = n - 1 move toward each other pair sum in a sorted array, palindromes, reverse, container with most water
Same direction slow = 0, fast = 0 fast explores, slow marks where to write remove duplicates, move zeroes, partitioning 
Opposite ends:   [ 1  3  4  6  8  10  13 ]        Same direction:  [ 0  1  0  3  12 ]
                   ^                    ^                           ^
                  left               right                         slow/fast

The core idea: each move eliminates many candidate pairs

The pair (left, right) is just one of the many pairs you could check. The power of the technique comes from this: after looking at the current pair, you can prove that a whole group of other pairs can never be the answer, so you skip them. For that proof you usually need structure in the data, most often a sorted array (or a symmetric check like a palindrome).

Example with a sorted array and target 13, pair (1, 13) has sum 14, which is too big. Since the array is sorted, 13 plus any other number is at least 13 + 1, so 13 can't be part of an answer with anything to its right of 1. Throw 13 away by moving right inward. If the sum had been too small, the same logic would let us discard the left value.

How to use it in JavaScript

let left = 0, right = arr.length - 1;
while (left < right) {          // pointers must not cross
  // look at arr[left] and arr[right], then move ONE of them
}

What problems look like this

  • Find a pair or triplet with a given sum, difference or property (usually sorted input).
  • Check or build something symmetric: palindrome, reverse, merge two sorted arrays.
  • Modify an array in place with O(1) extra space (remove, partition, dedupe).

Problem Example

Valid Palindrome. Ignoring case and non-alphanumeric characters, is the string a palindrome?

  • "A man, a plan, a canal: Panama" → true
  • "race a car" → false

Details Explanation

Step 1: the brute force

A palindrome reads the same forwards and backwards. The naive way is to clean the string (lowercase, drop punctuation), reverse a copy and compare. That works, but it builds extra strings (O(n) space). Two pointers can do the check in place.

Step 2: what does "palindrome" really require?

It means the characters at mirrored positions match: the first equals the last, the second equals the second last, and so on. We never need to compare a character with anything other than its mirror. So:

  • Compare the outermost pair.
  • If they differ → not a palindrome. Stop.
  • If they match → the question shrinks to the inner substring, which is the same problem but smaller.

Step 3: translate into two pointers

Place l at the start and r at the end. After comparing, move both inward by one. Stop when they meet or cross (l >= r); all pairs have been checked.

Step 4: handle characters we must ignore

The problem says to ignore spaces, commas and so on. Before each comparison:

  • while s[l] is not alphanumeric → l++
  • while s[r] is not alphanumeric → r--

Keep l < r in these inner loops so they can't run past each other.

Step 5: trace s = "Ab,a" (cleaned: aba)

Step l r s[l] s[r] Action
1 0 3 A a equal ignoring case → l=1, r=2
2 1 2 b , r skips the comma → r=1
3 1 1 b b equal → l=2, r=0
end l >= r → return true

For "race a car", the first compare is r vs r (ok), then a vs a (ok), then c vs c (ok), then e vs skipped to a → e !== a → false.

Step 6: the same idea on a sorted pair-sum

Sorted [1, 3, 4, 6, 8, 10, 13], target 13:

  • 1 + 13 = 14 > 13. Any pair ending in 13 is ≥ 1 + 13, so 13 is useless → right--.
  • 1 + 10 = 11 < 13. Any pair starting with 1 is ≤ 1 + 10, so 1 is useless → left++.
  • 3 + 10 = 13 → found.

Each step discards a whole row of pairs, so n elements need at most n steps.

Step 7: complexity

Every iteration moves at least one pointer inward → at most n moves → O(n) time, O(1) space.

Common mistakes

  • Moving both pointers when you should move only one (sorted pair-sum).
  • Forgetting l < r in the inner skip loops.
  • Using the same-direction technique on unsorted data when order matters.

Solution

function isPalindrome(s) {
  const isAlnum = (c) => /[a-z0-9]/i.test(c);
  let l = 0, r = s.length - 1;
  while (l < r) {
    while (l < r && !isAlnum(s[l])) l++;
    while (l < r && !isAlnum(s[r])) r--;
    if (s[l].toLowerCase() !== s[r].toLowerCase()) return false;
    l++; r--;
  }
  return true;
}
// Time O(n), Space O(1)

// Same-direction example: Move Zeroes (in place)
function moveZeroes(nums) {
  let w = 0;                          // next write position
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] !== 0) { [nums[w], nums[i]] = [nums[i], nums[w]]; w++; }
  }
}

Summary

  • Opposite ends: sorted array, pair-sum, palindrome, reversing.
  • Same direction: remove/partition in place with a write pointer.
  • Decide the move rule: in pair-sum, sum too small → l++, too big → r--.
  • Always guard l < r inside inner loops.

When Do I Use This?

  • The input is sorted (or can be sorted) and you search for a pair/triplet.
  • A palindrome or symmetric check is needed.
  • You must modify an array in place with O(1) extra space.

5. Sliding Window

Overview

Fundamentals

A window is a contiguous slice of the array described by two indexes, left and right. The sliding window technique moves that slice across the data one step at a time, keeping a running summary (sum, count, set of characters) and updating it incrementally instead of recomputing it.

nums = [ 1  12  -5  -6  50   3 ]
window :  [---------]               sum = 2
              [---------]           sum = 2 + 50 - 1 = 51   (add new, drop old)

Adding the new element on the right and removing the old element on the left costs O(1), so scanning every window costs O(n) total, instead of O(n·k) if you re-add k numbers each time.

Two types

Type Window size How it moves Examples
Fixed length Given k add nums[i], drop nums[i - k] each step max sum of size k, max average
Variable length Changes grow right always; move left only when the window becomes invalid (or to shrink it for a minimum) longest substring without repeats, smallest subarray with sum ≥ target

Core idea

Overlapping windows share almost all of their elements. Sliding exploits that overlap: only one element enters and one leaves per step.

For variable windows there is a second, important idea: left never moves backwards. Each index enters the window once and leaves at most once, so even with a while loop inside the for, the total work is O(n).

Template (variable window)

let left = 0;
for (let right = 0; right < n; right++) {
  // 1. add arr[right] to the window state
  while (/* window is invalid */) {
    // 2. remove arr[left] from the window state
    left++;
  }
  // 3. window [left..right] is valid: update the answer (length = right - left + 1)
}

What problems look like this

  • Contiguous subarray or substring (not subsequence).
  • "Maximum / minimum / longest / shortest ... of size k" or "with at most k ...".
  • The brute force recomputes a sum or count over overlapping ranges.

Problem Example

Maximum Average Subarray I. Find the contiguous subarray of length k with the largest average.

  • nums = [1,12,-5,-6,50,3], k = 4 → 12.75

Details Explanation

Part A: fixed window, Maximum Average Subarray (k = 4)

Step 1: brute force. For every start index, add up the next k numbers: (n − k + 1) windows × k additions = O(n·k). For n = 100,000 and k = 50,000 that's billions of operations.

Step 2: spot the overlap. Window 1 is [1, 12, -5, -6], window 2 is [12, -5, -6, 50]. They share 12, -5, -6. Only 1 left and 50 arrived, so newSum = oldSum - 1 + 50.

Step 3: build the first window by summing nums[0..k-1] (this is the only O(k) step).

Step 4: slide. For each i from k to n − 1: sum += nums[i] - nums[i - k], then best = max(best, sum).

Step 5: trace [1, 12, -5, -6, 50, 3], k = 4:

i Added Removed sum best
(initial) 1+12−5−6 = 2 2
4 50 1 2 + 50 − 1 = 51 51
5 3 12 51 + 3 − 12 = 42 51

Answer: 51 / 4 = 12.75. (We compare sums, since all windows have the same size.)

Part B: variable window, Longest Substring Without Repeating Characters

Step 1: brute force. Check every substring for repeats: O(n²) substrings × O(n) to check = O(n³), or O(n²) with a Set.

Step 2: define the window's rule. The window s[left..right] must contain no repeated characters. A Set holds the characters currently inside.

Step 3: expand right every step. If s[right] is already in the Set, the window is invalid.

Step 4: shrink from the left (remove s[left] from the Set, left++) until the duplicate is gone, then add s[right].

Step 5: record right - left + 1 after each step.

Step 6: trace s = "abca":

right char Action Set after left length best
0 a add {a} 0 1 1
1 b add {a,b} 0 2 2
2 c add {a,b,c} 0 3 3
3 a duplicate! remove a (left→1), then add {b,c,a} 1 3 3

Step 7: complexity. right moves n times and left moves at most n times in total → O(n) time, O(min(n, alphabet)) space.

Common mistakes

  • Using if instead of while when shrinking (one removal may not fix the window).
  • Off-by-one on length (right - left + 1, not right - left).
  • Forgetting to build the first window before the slide loop.

Solution

function findMaxAverage(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    best = Math.max(best, sum);
  }
  return best / k;
}
// Time O(n), Space O(1)

// Variable window template: longest substring without repeating characters
function lengthOfLongestSubstring(s) {
  const seen = new Set();
  let l = 0, best = 0;
  for (let r = 0; r < s.length; r++) {
    while (seen.has(s[r])) seen.delete(s[l++]); // shrink until valid
    seen.add(s[r]);
    best = Math.max(best, r - l + 1);
  }
  return best;
}

Summary

  • Fixed window: sum += new − old.
  • Variable window: expand r in a for, shrink l in a while when invalid.
  • Window length = r − l + 1.
  • Store window state in a number, Set or Map.

When Do I Use This?

  • Keywords: "contiguous subarray/substring", "longest/shortest", "at most k", "of size k".
  • You'd otherwise recompute a sum or count for overlapping ranges.

6. Sorting & Searching

Overview

Fundamentals

Sorting arranges data in order. JavaScript's arr.sort(compareFn) runs in O(n log n). Searching finds a value; on unsorted data you must check each element (O(n)), but on sorted data you can use binary search, which takes O(log n).

nums.sort((a, b) => a - b);   // ascending. WITHOUT a comparator, JS sorts as strings!
// [10, 9, 1].sort()  ->  [1, 10, 9]   (a classic bug)

The comparator returns a negative number if a goes first, positive if b goes first, and 0 for a tie.

Why sorting helps

Once sorted, equal values sit next to each other, pairs can be found with two pointers, and binary search becomes possible. A common strategy: "sort first (O(n log n)), then solve in O(n)." That beats an O(n²) brute force.

Binary search: fundamentals

Keep a range [lo, hi] that must contain the answer. Look at the middle element and discard half the range based on one comparison.

sorted: [-1  0  3  5  9  12]     target = 9
          lo       mid     hi
mid=3 < 9  -> throw away the left half -> lo = mid + 1

Each step halves the range, so 1,000,000 elements need about 20 comparisons.

Beyond "find a value": binary search on a condition

Binary search works whenever the answers go from false, false, ..., false, true, true, ..., true (a monotonic condition). Examples: first bad version, integer square root, smallest capacity that works. You find the boundary between false and true.

Two templates to memorize

  1. Exact match: loop while (lo <= hi), return the index on equality.
  2. First true: loop while (lo < hi), hi = mid when the condition holds, else lo = mid + 1.

What problems look like this

  • "Sorted array" in the statement, or "O(log n)" required.
  • "Find the minimum / maximum X such that ..." (search the answer space).
  • Duplicates, intervals or closest values, where sorting makes things adjacent.

Problem Example

Binary Search. Given a sorted array nums and target, return its index or -1.

  • nums = [-1,0,3,5,9,12], target = 9 → 4
  • target = 2 → -1

Details Explanation

Step 1: the brute force

Scan from the start and compare each element with the target: O(n). For 1,000,000 elements that could be 1,000,000 checks per search.

Step 2: use the sorted order to eliminate half

Compare the target with the middle element:

  • If nums[mid] === target → done.
  • If nums[mid] < target → because the array is sorted, everything at or before mid is also too small. Discard that whole left half (lo = mid + 1).
  • If nums[mid] > target → everything at or after mid is too big. Discard the right half (hi = mid - 1).

One comparison eliminates half of all remaining candidates.

Step 3: set up the loop

  • lo = 0, hi = n - 1 (the inclusive range that may hold the answer).
  • mid = lo + Math.floor((hi - lo) / 2). This form avoids overflow in other languages and is the habit to keep.
  • Keep looping while lo <= hi. When lo > hi the range is empty, so the target isn't there → return -1.

Step 4: trace nums = [-1, 0, 3, 5, 9, 12], target 9

Step lo hi mid nums[mid] Compare Next range
1 0 5 2 3 3 < 9 lo = 3
2 3 5 4 9 found return 4

Step 5: trace a missing target (2)

Step lo hi mid nums[mid] Compare Next range
1 0 5 2 3 3 > 2 hi = 1
2 0 1 0 -1 -1 < 2 lo = 1
3 1 1 1 0 0 < 2 lo = 2
end 2 1 lo > hi return -1

Step 6: the "first true" version

For problems like First Bad Version (versions 1..n, find the first bad one):

  • mid is bad (true) → the answer is mid or earlier, so hi = mid (keep mid!).
  • mid is good (false) → the answer is after mid, so lo = mid + 1.
  • Stop when lo === hi; that index is the first true.

Step 7: complexity

The range halves each loop: n → n/2 → n/4 ... → 1, so O(log n) time, O(1) space. If you must sort first, the total is O(n log n).

Common mistakes

  • sort() with no comparator on numbers.
  • Infinite loop from lo = mid instead of mid + 1 in the exact-match template.
  • Mixing the two templates' loop conditions (<= vs <).
  • Applying binary search to unsorted data.

Solution

function search(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
// Time O(log n), Space O(1)

// "First true" template (First Bad Version, sqrt, etc.)
function firstTrue(n, isTrue) {
  let lo = 1, hi = n;
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (isTrue(mid)) hi = mid; else lo = mid + 1;
  }
  return lo;
}

Summary

  • Always pass a comparator: arr.sort((a, b) => a - b).
  • Binary search needs sorted/monotonic data.
  • Two templates: exact match (lo <= hi) and first-true (lo < hi, hi = mid).
  • Sorting first is fine when it turns O(n²) into O(n log n).

When Do I Use This?

  • Input is sorted, or "sorted order makes it simple" (smallest missing, duplicates, intervals).
  • You see "find minimum X such that…" (binary search on the answer).
  • You need O(log n).

7. Stack & Queue

Overview

Fundamentals

A stack is a collection that follows LIFO: Last In, First Out. The last item you added is the first one you remove. Adding is called push and removing is called pop, and both take O(1) time. Picture a stack of plates: you only touch the top.

push 9      push 8      pop() -> 8      push 7
 [9]        [9,8]        [9]            [9,7]
             ^top                         ^top

Using an array as a stack (JavaScript)

The end of the array is the top of the stack:

const stack = [];
stack.push(9);          // [9]
stack.push(8);          // [9, 8]
stack.pop();            // returns 8, stack is [9]
stack[stack.length - 1] // peek at the top without removing
stack.length === 0      // is it empty?

pop() on an empty array returns undefined, so check emptiness before trusting the value.

Nested sequences: the main stack use case

When things open and close in a nested way (brackets, tags, function calls), the most recently opened thing must be closed first. That is exactly LIFO order.

{ [ ( ) ] }      opening  { [ (  -> push, in this order
                 closing  ) ] }  -> pops come out in the reverse order: ( then [ then {

Other stack patterns

  • Undo / backspace simulation: push letters, pop on #.
  • Monotonic stack: keep the stack sorted so you can find the "next greater element" in O(n).
  • Evaluate expressions: push operands, pop when you see an operator.

Queue: fundamentals

A queue is FIFO: First In, First Out, like a line at a shop. Items join at the back (enqueue) and leave from the front (dequeue).

enqueue 1,2,3:   front [1, 2, 3] back      dequeue -> 1      front [2, 3] back

In JavaScript, arr.shift() removes from the front but is O(n). For large inputs, keep a head index and just move it forward (see the Queue class in the solution). Queues appear in order-of-arrival problems, "recent N events" counters and breadth-first search.

What problems look like this

  • Balanced / valid brackets, nested structures, decoding strings.
  • "Next greater / smaller element", daily temperatures.
  • Simulating a process with undo, or a waiting line.

Problem Example

Valid Parentheses. A string of ()[]{} is valid if brackets close in the correct order.

  • "()[]{}" → true
  • "(]" → false
  • "([)]" → false

Details Explanation

Step 1: why not just count brackets?

Counting opens vs closes fails on "([)]": there are two opens and two closes, but the order is wrong. Validity depends on order and type, not only totals.

Step 2: think about what must happen

When we see a closing bracket, it must close the most recent bracket that's still open. "Most recent unmatched" is the definition of the top of a stack, so a stack is the natural tool.

Step 3: the rules

Scan left to right:

  1. Opening bracket ((, [, {) → push it. It's now waiting for its partner.
  2. Closing bracket → pop the top. It must be the matching opener. If it isn't (or the stack was empty), the string is invalid, so return false right away.
  3. After the loop, the stack must be empty. Anything left is an opener that never got closed (e.g. "((").

Step 4: the lookup table

pairs = { ")": "(", "]": "[", "}": "{" } lets us check "is this a closer?" with c in pairs and find its expected opener with pairs[c].

Step 5: trace "{[()]}" (valid)

{ push {
[ push { [
( push { [ (
) pop ( matches { [
] pop [ matches {
} pop { matches empty → true

Step 6: trace "([)]" (invalid)

) pop gives [, but ) needs ( mismatch → false

Step 7: the two other failure cases

  • ")": the stack is empty, pop() returns undefined, which isn't "(" → false.
  • "((": no mismatches, but the stack still holds 2 items at the end → false.

Step 8: complexity

Every character is pushed at most once and popped at most once → O(n) time, up to n items stored → O(n) space.

Common mistakes

  • Forgetting the final stack.length === 0 check.
  • Popping from an empty stack and treating undefined as a match.
  • Using shift() on a huge array as a queue.

Solution

function isValid(s) {
  const pairs = { ")": "(", "]": "[", "}": "{" };
  const stack = [];
  for (const c of s) {
    if (c in pairs) {
      if (stack.pop() !== pairs[c]) return false;
    } else {
      stack.push(c);
    }
  }
  return stack.length === 0;
}
// Time O(n), Space O(n)

// Simple queue with head pointer
class Queue {
  constructor() { this.items = []; this.head = 0; }
  enqueue(x) { this.items.push(x); }
  dequeue() { return this.items[this.head++]; }
  get size() { return this.items.length - this.head; }
}

Summary

  • Stack = matching/nesting, undo, "next greater element" (monotonic stack).
  • Queue = FIFO order, BFS, recent-window counts.
  • Empty stack: pop() returns undefined, so check before trusting it.
  • Process, then verify nothing is left over.

When Do I Use This?

  • Brackets, nested expressions, backspace/undo simulation.
  • "Next greater/smaller element" (monotonic stack).
  • Tasks processed in arrival order.
